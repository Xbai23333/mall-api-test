# Mall 接口自动化测试用例清单

> 基于项目当前 `tests/` 目录及 `data/login_cases.json`、`data/order_status.json` 整理。预期结果以现有自动化断言为准；文档中的“当前接口行为”不代表理想的接口设计。

## 测试概况

| 模块 | 用例数量 | 类型 |
|---|---:|---|
| 登录认证 | 6 | 接口测试 |
| 商品管理 | 13 | 接口测试 |
| 商品分类 | 11 | 接口测试 |
| 订单管理 | 16 | 接口测试 |
| 断言工具 | 4 | 单元测试 |
| 数据库一致性校验 | 1 | 接口与数据库一致性测试 |
| **合计** | **51** | **46条接口测试 + 4条单元测试 + 1条数据库一致性测试** |

## 执行方式

```bash
python -m pytest tests/ -q
python -m pytest tests/ --collect-only -q
```

说明：需要按项目配置启动后端及依赖服务，接口测试使用配置的测试账号。部分用例依赖数据库中的商品、分类和订单测试数据。

## 说明与注意事项

- `assert_api_response(response)` 的默认 HTTP/业务状态码检查以项目断言工具的默认配置为准；此处不推断未展示的实现细节。
- 登录异常用例的 `expected_messages` 是允许匹配的消息集合；并非要求一次响应同时包含所有消息。
- 商品与分类的非法分页用例记录当前接口返回空列表的行为，并不意味着非法分页参数应被视为有效输入。
- 商品ID、分类父ID、订单ID使用字符串 `abc` 时，现有测试断言的是 HTTP 400 和认证相关业务错误；这是当前接口行为，值得后续单独评估。
- 订单状态 `0`～`4` 仅表示测试数据中的数值，本文不推断对应的业务状态名称。
- 订单详情和按订单编号查询使用列表中的真实订单作为前置数据，测试环境需存在可用订单。
- 断言工具4条为 Mock 单元测试，不会实际请求商城后端。
- 测试用例编号是文档编号；参数化用例的 pytest ID 仍沿用脚本中的原始编号。
- 数据库一致性测试需要提前启动Mall后端和MySQL，并正确配置数据库连接信息；该用例只执行SELECT查询，不修改数据库数据。
